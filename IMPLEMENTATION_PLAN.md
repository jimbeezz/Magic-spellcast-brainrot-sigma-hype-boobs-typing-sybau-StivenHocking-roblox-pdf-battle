# План реализации (поэтапно)

Проект: `SpellCaster: Arena`  
Цель: двигаться маленькими итерациями и не уходить в арт до стабилизации core-loop.

## Утвержденный стек

- Клиентская игра: `C# + Windows Forms`.
- Backend API: `C#` (`ASP.NET Core Minimal API`).

## Что сделано сейчас (состояние репозитория)

- `SpellCaster.sln`: создано решение.
- `client/SpellCaster.WinForms`: создан WinForms-проект, окно `Form1` с плейсхолдерами экранов и списком выученных заклинаний (паттерны видны).
- `backend/SpellCaster.Api`: минимальный API (эндпоинты `/health`, `/api/meta`).
- Документы: `README.md`, `TZ.md`, `GDD_v1.md`, этот план.

## Как работать по плану

- Каждый этап завершается только после выполнения критериев "Готово".
- Новые фичи не добавляем, пока текущий этап не стабилен.
- После каждого этапа делаем короткий playtest и фиксируем проблемы.

## Этап 0. Технический старт

### Задачи

- Утвердить стек и архитектуру (Windows Forms + backend API, формат данных, структура проекта).
- Создать базовую структуру папок:
  - `backend/SpellCaster.Api`
  - `client/SpellCaster.WinForms/Core` (чистая логика, без UI)
  - `client/SpellCaster.WinForms/Data` (JSON/ресурсы контента)
  - `client/SpellCaster.WinForms/UI` (общие UI-компоненты/хелперы)
  - `client/SpellCaster.WinForms/Screens` (экраны как `UserControl` или `Panel`)
- Подготовить базовые data-файлы:
  - `spells.json`
  - `enemies.json`
  - `progression.json`
- Настроить запуск:
  - запуск клиента (WinForms) из Visual Studio / `dotnet run`
  - запуск API из `backend` (опционально на этом этапе)

### Готово, если

- Проект запускается локально без ошибок.
- Есть навигация между плейсхолдер-экранами `MainMenu`, `Loadout`, `Battle`, `Exam`, `Results`.
- В боевом UI есть панель “выученные заклинания” с видимыми паттернами (без необходимости запоминать).
- API отвечает на `/health` (если backend включаем в демо).

### Оценка

- 0.5-1 день.

## Этап 1. Ядро ввода заклинаний (без боя)

### Задачи

- Реализовать `SpellInputEngine` (класс в `Core`), который принимает:
  - `pattern` (строка),
  - окно времени `castWindowMs`,
  - поток введенных символов.
- Поддержать посимвольную валидацию:
  - верный символ,
  - ошибка,
  - завершение паттерна.
- Добавить таймер каста через `System.Windows.Forms.Timer`.
- Сделать UI-прототип экрана ввода (отдельный `UserControl` или панель на форме):
  - отображение паттерна,
  - подсветка позиции (сколько введено),
  - состояния: OK / ошибка / timeout / успех.
- Учесть mixed-input (латиница, кириллица, спецсимволы, alt-символы).
  - Важно: использовать `KeyPress` (символы), а не только `KeyDown` (клавиши).

### Готово, если

- Любой паттерн из `GDD_v1` корректно проходит/фейлится.
- Таймер стабильно завершает каст по истечению времени.
- Нет пропусков символов при быстром наборе.
  - Проверка: быстро набрать `пр@ок^az/*za` и `☻↓→♫kZ`.

### Оценка

- 1-2 дня.

## Этап 2. Боевая петля Arena 1v1 (MVP combat)

### Задачи

- Подключить `PlayerState` + `EnemyState` (в `Core`):
  - HP,
  - mana,
  - таймер атаки врага.
- Внедрить формулу урона из `GDD_v1`.
- Добавить базовые эффекты:
  - `slow`,
  - `interrupt`,
  - `shield`.
- Реализовать победу/поражение и переход на экран результатов.
- Добавить боевой лог событий.
  - UI: `ListBox`/`RichTextBox` для лога, `ProgressBar` для HP/mana.

### Готово, если

- Игрок может провести полноценный бой с 1 врагом от старта до результата.
- Уязвимости/сопротивления реально влияют на урон.
- `interrupt` прерывает специальные атаки по правилам.

### Оценка

- 2-3 дня.

## Этап 3. Loadout и прогрессия

### Задачи

- Реализовать систему выученных заклинаний (`unlockedSpells`).
- Добавить экран выбора loadout перед боем (4 слота):
  - слева список выученных,
  - справа 4 выбранных слота,
  - кнопки Add/Remove или double-click.
- Ограничить loadout до 4 активных слотов (MVP).
- В бою показать панель известных/доступных заклинаний с паттернами.
- Добавить XP-награды и unlock tier-ов по порогам из `GDD_v1`.
  - Сохранение прогресса локально (JSON в папке пользователя).

### Готово, если

- Перед боем можно выбрать 4 заклинания и начать матч.
- В бою нельзя использовать спеллы вне loadout.
- После побед открываются новые tier-спеллы по условиям.

### Оценка

- 1-2 дня.

## Этап 4. Контент Arena (6 врагов)

### Задачи

- Подключить всех 6 врагов из `GDD_v1`.
- Реализовать уникальные механики:
  - щит голема,
  - сдвиг окна у элементаля,
  - копирование у Dark Magus,
  - `Reality Twist` у Chaotic Magus,
  - `Inferno Breath` + Ward-check у дракона.
- Прогнать первичный баланс чисел (урон, мана, окна каста).

### Готово, если

- Все 6 врагов работают с собственными механиками.
- Финальный бой с драконом проходим при правильной тактике.
- Нет софтлоков в длинной цепочке боев.

### Оценка

- 2-3 дня.

- Реализовать scoring из `GDD_v1`:

  - `maxCombo`,
  - `accuracy`,
  - `castsPerMinute`.
- Сделать экран результатов и сохранение лучшего результата локально.

### Готово, если

- `Exam` полностью работает независимо от Arena.
- В `strict` первая ошибка завершает попытку.
- Метрики корректно считаются на 100+ кастах подряд.

### Оценка

- 1-2 дня.
